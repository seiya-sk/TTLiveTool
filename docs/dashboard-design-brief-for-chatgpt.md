# TikTokライブ分析ダッシュボード — デザイン刷新用資料

この資料は、既存コード(`dashboard/src/`)を実際に確認して作成した、現状のダッシュボードの構造・表示内容・データの性質のまとめです。ChatGPTにビジュアルデザイン(配色・レイアウト・見た目)を検討してもらうための素材として、そのまま渡してください。

## このアプリについて

TikTokライブ配信の分析ツールです。配信中のコメント・ギフト・視聴者数などをリアルタイムに記録し、配信終了後にそのデータを振り返るためのダッシュボードです。利用者は大きく2種類:

- **事務所スタッフ**: 担当ライバーの配信を振り返り、次回配信の改善につなげるために見る
- **社内(運用担当)**: システムの利用状況・コスト・データ量などを管理するために見る

## 1. サイトマップ / 画面構成

```
NavBar(全画面共通): 「TikTokライブ分析」ロゴ + ホーム / ライバー一覧 / ライブ一覧 / 設定

/                       ホーム(KPI概観 + 直近の配信)
├─ /streamers           ライバー一覧(テーブル)
│   └─ 行クリック → /sessions?streamerId=X
├─ /sessions            ライブ一覧(3タブのランキング、?streamerId=で絞り込み可)
│   └─ 行クリック → /sessions/[id]
│       └─ /sessions/[id]     ライブ詳細(このアプリの中心画面)
└─ /settings            設定ハブ(3枚のカード)
    ├─ /settings/tokens      AIレポートのトークン・コスト管理
    ├─ /settings/data        データ容量の管理
    └─ /settings/streamers   ライバーの追加・アーカイブ管理
```

画面数は7つ(+設定ハブ)。ページ遷移は基本的に「一覧→詳細」の一方向で、深い階層はありません。

## 2. 各画面の要素 と 3. データの性質

### ホーム `/`
| 要素 | 内容 |
|---|---|
| KPIカード×3 | 登録ライバー数、総配信数(いずれもクリックで一覧へ)、今月のダイヤ合計 |
| 直近の配信リスト | 直近5件を「ライバー名 ー 日時(配信時間)」の1行リンクで表示 |

シンプルな「入口」画面。データは単純な集計値のみ。

### ライバー一覧 `/streamers`
| 要素 | 内容 |
|---|---|
| テーブル1枚 | ライバー名(検索可)、配信数、直近配信日、累計ダイヤ |

行クリックでそのライバーの配信一覧へ絞り込み遷移。**利用者/目的**: 事務所スタッフが「担当ライバーの実績を一覧で把握」するための画面。

### ライブ一覧 `/sessions`
| 要素 | 内容 |
|---|---|
| 絞り込みバナー | `?streamerId=`指定時に「〇〇で絞り込み中」と表示 |
| 3タブのランキングテーブル | ダイヤランキング / 新規フォロワーランキング / 同接ランキング。各タブ共通で「日付・配信者」列+タブごとの指標列(降順ソート) |

**データの性質**: 3種の指標を配信横断でランキング表示。**利用者/目的**: 事務所スタッフ・社内共通で「どの配信が良かったか」を比較する画面。

### ライブ詳細 `/sessions/[id]` — アプリの中心画面
最も要素が多く、デザインの見せ所になる画面です。

**KPIカード(12枚)**: 平均視聴者数、最高同接、総視聴者数、総ギフト(ダイヤ)、コメント数、新規フォロー、バトル回数、ギフト送信率、宝箱出現数、宝箱コイン合計、平均視聴時間、タップスルー率。

- このうち「新規フォロー」「バトル回数」「ギフト送信率」の3つには **good/warn の判定バッジ**が付く(基準値は`lib/baselines.ts`にハードコード: ギフト送信率2.5%以上、新規フォロー10人以上、バトル頻度40〜50分に1回)
- 「平均視聴時間」「タップスルー率」の2つは**「計測不可」バッジ固定**(視聴者ごとの退室時刻を記録していないため、原理的に算出不可。捏造せず正直に「計測不可」と表示する設計)

→ **デザイン上の要注意点**: 12枚のKPIカードの中に「良い/注意/計測不可」という3種の状態が混在する。一目で状態が分かる見た目の工夫が欲しい。

**メイン複合グラフ(このアプリで最も重要なビジュアル要素)**:
- 系列ON/OFFを切り替えるチェックボックス行(6系列、それぞれ色スウォッチ付き): 視聴者数(青・折れ線)/ コメント数(緑・半透明バー)/ ギフト(ピンク・**対数スケール**バー)/ バトル(オレンジ)/ スクショ(水色)/ 宝箱(紫)
- 本体グラフ(横軸=配信開始からの経過時間、分単位): 視聴者数を折れ線、コメント数を半透明バー(左Y軸)、ギフトのダイヤ数を対数スケールのバー(右Y軸)
- **ギフトが対数スケールな理由**: 通常は数十〜数百ダイヤの投げ銭に混じって、数万ダイヤ級の高額ギフトが単発で出ることがあり、線形スケールだと大半のデータが潰れて見えなくなるため
- 本体グラフの下に、細い帯(高さ26px)が3本並ぶ「イベントレーン」: バトル検知 / スクショ撮影 / 宝箱開封、それぞれ点(5px丸)がタイムライン上に散らばる散布図。ホバーでツールチップ(バトル→対戦相手ID、スクショ→「クリックでプレビュー」、宝箱→獲得コイン・当選者数・送り主・開封時刻)
- スクショの点をクリックすると画像プレビューパネルが開く

**データの性質の要点(デザイナーへの申し送り)**:
- 視聴者数: 1分単位に間引いた連続的な時系列(折れ線向き)
- ギフト: 外れ値のある分布(対数スケール前提)
- バトル検知: 疎らな時刻マーカー、密集することがある(実例: 1配信で生ログ47件→重複除去後14件のバトルに集約するロジックが既にある)
- スクショ・宝箱: 同じく疎らな時刻マーカー、画像/詳細への入口を兼ねる

**AI分析レポート**: 生成日時+Markdown形式のAI生成テキスト(react-markdownで描画)。未生成の場合は生成コマンドを案内する空状態。

**6タブの詳細テーブル**: バトル相手 / ギフトランキング / ギフト明細 / 入室管理 / フォロー / コメント。

**利用者/目的**: 事務所スタッフが「この配信で何が起きたか」を振り返り、AIレポートの提案を確認するための画面。社内スタッフも異常確認や詳細データ抽出で使う。

### 設定 `/settings`
3枚のカード(トークン管理・データ管理・ライバー管理)へのハブ。**利用者**: 社内(運用担当)のみ。事務所スタッフは通常見ない画面。

### トークン管理 `/settings/tokens`
期間選択(今月/先月/全期間/期間指定のピルボタン)+KPIカード4枚(対象レポート数、input/outputトークン合計、合計コスト円+USD)+為替レート等の編集欄+ライバー別/ライブ別の使用量テーブル2枚。**目的**: AIレポート生成のコスト管理。

### データ管理 `/settings/data`
KPIカード3枚(合算データ量、DBファイル、スクショ画像)+種類別内訳(自作の横棒グラフ、5色を巡回: `#0ea5e9 #f59e0b #16a34a #db2777 #94a3b8`)+ライバー別/ライブ別の容量テーブル2枚。**目的**: ストレージ使用量の把握。

### ライバー管理 `/settings/streamers`
追加フォーム+テーブル(状態バッジ: 有効=緑/アーカイブ済み=グレー、ライバー名、TikTok ID、配信数、直近配信日、操作)。削除は物理削除ではなく論理アーカイブ(元に戻せる)。

### 共通コンポーネント
- **DataTable**: ほぼ全画面で使い回されるテーブル。検索・列フィルタ・クリックソート・50件区切りのページング付き
- **Tabs**: 下線スタイルのタブ切り替え

## 5. 現状のデザイン(出発点)

- **配色はほぼモノクロ**。CSS変数は`--background`/`--foreground`の2つだけで、ブランドカラーと呼べるものが画面の骨格(ナビ・カード・テーブル)には一切ない。カード背景や罫線はすべて`foreground`を数%だけ混ぜた濃淡のみ
- 色が使われているのは**グラフの系列色・状態バッジ・エラー表示だけ**(青#2563eb・緑#16a34a・ピンク#db2777・オレンジ#ea580c・紫#7c3aed・水色#0ea5e9など)
- ライト/ダークモードは`prefers-color-scheme`による自動切り替えのみ(手動トグルなし)
- **フォントはArial/Helvetica**(Webフォント不使用)、装飾なし
- コンポーネントライブラリは未使用(Tailwindも不使用)、すべて手書きCSS
- 見た目の印象: 角丸4〜8px・影なし・グラデーションなし、機能一辺倒の「社内ツール」然とした無個性なルック

→ **これが刷新の出発点**です。データを見せる骨格(テーブル・カード・グラフのレイアウト構造)は現状維持でよいものの、配色・タイポグラフィ・カードや境界線の表現に、今は存在しない個性を足したい、というのが今回の依頼意図です。

## デザインの方向性(ご要望)

- **ポップで親しみやすい**配色・見た目にしたい。色を積極的に使い、TikTokライブという明るい題材に合わせる
- 利用者は事務所スタッフ・社内の両方。専門的すぎず、かつ分析ツールとして必要な情報量は保つ
- **見た目の美しさ**と**情報の分かりやすさ**、両方をバランスよく。特にライブ詳細画面のKPIカード(良い/注意/計測不可の3状態)とメイン複合グラフ(6系列+対数スケール)は、情報密度が高いままでも見やすくなる工夫がほしい
